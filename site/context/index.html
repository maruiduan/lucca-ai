    上下文与提示词：模型到底「看到」了什么

    第一部分 · 大模型本身 · 第 4 篇　|　约 13 分钟　|　3 个小实验

    一句话结论模型每次回答前，看到的只是一长串 token：系统提示、你们之前的全部对话、你刚说的话，按固定格式拼在一起。除此之外它什么都不记得。这串东西能有多长，叫上下文窗口；写好提示词，本质上就是把这串东西喂好。

    01它没有记忆：每一轮都从头读一遍

    和聊天机器人聊了十几轮，它好像记得你说过的一切。其实模型本身不记得任何事：参数在训练完以后就固定了，聊天不会改变它。它「记得」，是因为聊天软件每一轮都把之前的全部对话重新发给它，让它从头读一遍，再接着写下一段回答。

    可以把它想成一位记性为零、但阅读飞快的专家：每次你提问，助理都把整本对话记录递给他，他读完再回答。你说「它讲的是什么」，他能知道「它」指哪部电影，全靠记录里写着。

    小实验 ①：拼一次对话，看模型收到什么格式为示意
    系统提示（由做产品的人设定，用户一般看不到）：
    这一轮真正送进模型的整串文字（约 0 个 token，按每字约 1 个粗算）：

    回答都是我们手写的示意。注意每一轮这串文字都从头开始、越来越长；打开「不把历史发过去」，看模型为什么突然听不懂「它」。

    02系统提示：放在最前面的「岗位说明」

    那串文字的最开头，通常是一段系统提示（system prompt），由做产品的人写：你是谁、用什么语气、能做什么不能做什么、今天几号。它每一轮都会被放在最前面，所以对整场对话影响很大。上一篇讲过，模型在后训练时就学过「系统提示的话要格外重视」。

    这也解释了为什么同一个模型，在不同的 App 里「性格」不一样：底下也许是同一个模型，只是系统提示不同。

    03上下文窗口：一次能看多长

    模型一次能读进去的 token 数是有上限的，叫上下文窗口。它从早年的一两千个 token，增长到今天的几十万甚至上百万个：

    模型年份上下文窗口
    GPT-220191,024 个 token
    GPT-320202,048 个 token
    GPT-4 Turbo2023128,000 个 token（超过 300 页文字）
    Gemini 1.5 Pro2024预览版最多 100 万个 token

    为什么不能无限长？第 1 篇讲过，注意力要让每个 token 和前面的每个 token 都「比一比」。长度翻一倍，要比较的对数就翻四倍，算力和内存都跟着涨。装满以后，聊天软件只好丢掉最早的内容，或者把旧对话压缩成一段摘要再放进去。

    小实验 ②：窗口装满了会怎样玩具长度
    系统提示你贴进来的长文档你说的话模型的回答旧对话摘要
    已聊轮数 4窗口：2,000 个 token（玩具）
    装进窗口–
    被挤出去–
    注意力要比的词对–

    窗口够大也不等于都能用好。2023 年斯坦福等的研究《Lost in the Middle》发现：把关键信息放在长上下文的开头或结尾，模型用得最好；放在中间，效果明显变差。所以重要的要求，放在提示的开头或结尾更稳妥。

    04提示词：把要求说清楚

    既然模型看到的只有这串文字，提示词写得好不好，就直接决定回答好不好。OpenAI 和 Anthropic 的官方指南给的建议大同小异：

    • 说清楚任务和用途：要什么、给谁看、用来干嘛；
    • 给背景：它不知道你的处境，你不说它只能猜；
    • 给例子：一两个示范，比一大段描述更管用；
    • 规定格式：要几条、多长、用表格还是列表；
    • 允许它说不知道，复杂问题让它一步步想（第 5、7 篇会讲为什么）。
    小实验 ③：给提示词加积木示意回答

    任务：「解释为什么天空是蓝色的」。点下面的积木，加进提示词，看回答怎么变。

    回答是我们手写的示意，用来说明「说得越清楚，回答越贴合」，不是某个真实模型的原话。

    「给例子」背后有个专门的名字：上下文学习（in-context learning）。2020 年的 GPT-3 论文发现，不用重新训练，只要在提示里放几个「输入 → 输出」的示范，模型就能照着做新任务。比如：

    苹果 → 水果 胡萝卜 → 蔬菜 香蕉 → 水果 土豆 → ？

    模型会接上「蔬菜」。它没有因此「学会」分类，参数一点没变；它只是在上下文里看出了规律，顺着规律往下接。这也正是第 1 篇那个「猜下一个字」的本事。

    05比措辞更重要的：往上下文里放什么

    写提示词，常被当成找「咒语」。但读到这里你会发现，更关键的是把对的信息放进那串文字里：相关的资料、清楚的要求、合适的例子。这件事越来越被称为「上下文工程」。

    后面几篇都和它有关：第 6 篇的 RAG，就是自动把相关资料检索出来塞进上下文；第二部分的智能体，则是让模型一边干活、一边把工具的结果不断加进上下文。

    延伸阅读：这一篇讲的是一问一答时怎么用好上下文。到了会自己调用工具、一干就是上百步的智能体，上下文会越堆越满，怎么取舍就成了一门专门的手艺，见第二部分的《上下文工程》。

    06记住这些就够了

    1. 模型没有记忆。每一轮，App 都把系统提示 + 全部历史 + 你的新消息拼成一串 token 发给它，它只根据这串东西回答。
    2. 上下文窗口是这串东西的长度上限；装满后旧内容会被丢掉或压缩，而放在中间的信息也更容易被忽略。
    3. 好提示词 = 说清楚任务、给背景、给例子、定格式。放进上下文的信息，比措辞技巧更重要。
