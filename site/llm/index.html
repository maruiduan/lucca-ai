    什么是 LLM：一台很会「猜下一个字」的机器

    第一部分 · 大模型本身 · 第 1 篇　|　约 15 分钟　|　4 个小实验

    一句话结论大语言模型（LLM）只做一件事：看着前面的文字，算出下一个字（token）各有多大可能，挑一个写上，再接着猜。你看到的长篇回答，就是这样一个字一个字「猜」出来的。

    01先打个比方：手机输入法

    你在手机上打「今天天气」，输入法上方马上冒出「很好」「不错」「怎么样」。它没在思考天气，只是见过太多人这么打字，知道这几个词最常跟在后面。

    大语言模型做的是同一件事，只是规模大得多：它读过的文字以万亿个 token 计，看得见的「前文」可以是好几页甚至一整本书，猜得也准得多。Jay Alammar 在讲解 GPT-2 时就打过这个比方：GPT-2 基本上就是输入法的「下一个词联想」，只不过大得多、复杂得多。

    如果你一直点输入法给的第一个词，往往会写出一段车轱辘话；大模型也有同样的毛病，后面讲「温度」时你会亲手看到。

    02LLM 这三个字母是什么意思

    • Large（大）：模型里可调的数字（叫参数）非常多。2020 年的 GPT-3 有 1750 亿个参数。
    • Language（语言）：它处理的是文字，学的是文字的规律。
    • Model（模型）：一个数学公式（一个巨大的神经网络），输入一段文字，输出「下一个 token 的概率表」。

    ChatGPT 里的 GPT 也可以拆开看：Generative（会生成）、Pre-trained（事先在海量文字上训练过）、Transformer（用的是 2017 年提出的一种网络结构）。这三个词后面都会讲到。

    参数可以想成调音台上的旋钮。训练就是根据大量文字，自动把上千亿个旋钮一点点拧到「最会猜下一个字」的位置。训练怎么拧旋钮，留到下一篇「预训练」细讲。

    03一路走来：从数数到 ChatGPT

    「猜下一个字」这个想法一点都不新，新的是猜的方法。往下滑，看这七十多年是怎么一步步走过来的：

    1948
    香农：用统计猜下一个字母
    信息论之父香农在论文里演示：只统计「哪个字母后面常跟哪个字母」，就能拼出越来越像英语的句子。这就是最早的 n-gram 思路：只看前面 n−1 个字。
    1990s–2000s
    n-gram 语言模型进入实用
    语音识别、机器翻译、输入法大量使用这种「数次数」的模型。缺点也明显：只能看前面两三个词，没见过的组合就完全不会。
    2003
    神经网络语言模型
    Bengio 等人用神经网络来猜下一个词，并且顺手给每个词学出一串数字（词向量），意思相近的词数字也相近，所以没见过的组合也能举一反三。
    2013
    word2vec：词向量出圈
    Mikolov 等人提出快速学习词向量的方法，出现了著名的例子：「国王 − 男人 + 女人 ≈ 女王」。
    2014
    RNN、LSTM 和 seq2seq
    循环神经网络（其中常用的 LSTM 早在 1997 年就提出了）像人读书一样，一个词一个词往后读，边读边更新「记忆」。2014 年它被用来做机器翻译，同年还出现了最早的「注意力」机制。问题是：句子一长就容易忘前面，而且只能一个词接一个词算，没法并行加速。
    2017
    Transformer：《Attention Is All You Need》
    Google 的研究者提出完全靠「注意力」的结构，丢掉了一个词一个词往后读的做法：所有词同时互相「看」，可以在显卡上大规模并行训练。今天几乎所有大模型都基于它。
    2018
    GPT 和 BERT
    OpenAI 的 GPT（约 1.17 亿参数）先在大量文字上「预训练」学接话，再针对任务微调；同年 Google 的 BERT 也走了预训练路线。
    2019
    GPT-2：15 亿参数
    模型放大约十倍，已经能写出连贯的长段文章。
    2020
    GPT-3：1750 亿参数
    再放大一百多倍。人们发现：只要在提示里给几个例子，它就能照着做新任务，不用专门再训练。
    2022
    InstructGPT 与 ChatGPT
    用人类示范和人类打分（RLHF）做「后训练」，让模型从「会接话」变成「会好好回答问题」。2022 年 11 月 30 日 ChatGPT 发布，大模型走进大众视野。
    2023 至今
    百花齐放
    更大更强的闭源模型、可以自己下载运行的开放权重模型（比如 Meta 的 Llama 系列）相继出现；模型开始能看图、听声音，能读的上下文越来越长，还出现了先「想一想」再作答的推理模型，以及会自己调用工具的智能体（第二部分会讲）。

    一条主线：看得越来越远（从前两个词到整本书）、对词的理解越来越「懂意思」（从死记次数到向量）、规模越来越大（参数从几百万到上千亿）。

    下面我们按顺序把每一步拆开，每一步都配一个能动手的小实验。

    05第一步：把文字切成 token

    模型不直接认识「字」，它先把文字切成一小块一小块，叫 token（可以译成「词元」）。一个 token 可能是一个字、一个词、半个英文单词，或者一个标点。每个 token 在模型的「词表」里有一个编号，模型真正看到的是这串编号。

    为什么不按字或按词切？按字母切太碎，句子会变得特别长；按整词切，词表又会无穷大，碰到新词就傻眼。所以真实模型用一种叫 BPE 的方法，从大量文字里统计出最常一起出现的片段作为 token：常见的词整块保留，罕见的词拆成几块。比如 3Blue1Brown 的例子里，英文 cleverest 被切成了 cle / ve / rest 三块。

    小实验 ①：看看一句话被切成几块玩具切分器

    这是一个只有几百个词的玩具切分器，用「从左往右找最长的已知词」来切；没见过的字会单独成块（标「单字」）。真实模型的词表有几万到几十万个 token，切法也不一样，可以去 OpenAI 的 Tokenizer 页面试真的。

    有两点值得记住：

    • 按 OpenAI 的经验，英文里 1 个 token 大约是 4 个字母、四分之三个单词；中文和其他语言的比例不一样，也因模型而异。
    • 模型「能读多长」、使用时「按多少计费」，用的都是 token 数，不是字数。

    06第二步：把 token 变成一串数字（向量）

    编号本身没有意义：「猫」是 1234 号，「狗」是 5678 号，编号离得远不代表意思离得远。所以模型给每个 token 配一长串数字，叫向量（embedding，嵌入）。这串数字可以看成一个点在空间里的坐标。

    神奇的是，训练完以后，意思相近的词，坐标也靠得近；甚至某些方向也有了意思，比如从「男人」指向「女人」的方向，和从「国王」指向「女王」的方向差不多。GPT-3 的每个向量有 12,288 个数字，也就是 12,288 维，我们画不出来，下面用一张二维的小地图来示意：

    小实验 ②：词语地图手工摆放的示意图

    点图上的词（或下面一排按钮），看离它最近的三个词。

    坐标是我们手工摆的，只为说明「近义词挨在一起」的现象。真实模型的向量是训练出来的、有成千上万维；3Blue1Brown 也提到，「国王 − 男人 + 女人」在真实模型里只是落在「女王」附近，并不完全相等。

    一开始，每个 token 的向量只代表这个词本身，不管上下文。可「苹果」在「吃了个苹果」和「苹果发布会」里明显不是一回事，这就要靠下一步。

    07第三步：注意力，让词互相「看一眼」

    Transformer 的核心叫注意力（attention）。在这一步，每个词都会问一句：「前面哪些词跟我有关？」然后把那些词的信息按相关程度掺进自己的向量里。掺完以后，「苹果」的向量就带上了「吃」或「发布会」的味道。

    Jay Alammar 用过一个很好懂的比方：像在档案柜里查资料。每个词拿着一张写着「我想找什么」的便签（查询），去对照其他词身上的标签（键），越对得上，就从那个词的抽屉里（值）多拿一点内容。

    像 GPT 这样「往后写」的模型还有一条规矩：每个词只能看它自己和前面的词，看不到后面，因为写到这里时，后面的字还没写出来呢。

    小实验 ③：点一个词，看它在「注意」谁权重为手工设定

    颜色越深、百分比越大，表示越受关注；灰掉的是「还看不到」的后文。真实模型的注意力权重是算出来的，而且一个模型有几十层、每层有很多组注意力（叫「多头」），各自关注不同的东西，比这里复杂得多。

    注意力之后，每个向量还会单独经过一个小神经网络（叫前馈层），可以想成对每个词「再琢磨一下」。一次注意力加一次琢磨，算一层；大模型会把这样的层叠几十上百层，越往上，向量里装的上下文信息越丰富。最后，最末尾那个位置的向量里，装着猜下一个字所需的全部信息。

    08第四步：算出每个候选的概率

    模型拿最后那个向量，和词表里每一个 token 比一比「有多配」，给每个 token 打一个分，这些分叫 logits。分数可正可负，加起来也不等于 1，还不是概率。

    于是要用一个叫 softmax 的公式把分数换成概率：先对每个分数取 e 的次方（让它们都变成正数，而且拉开高分和低分的差距），再除以它们的总和，这样所有候选的概率加起来正好是 100%。分数最高的那个概率最大，但别的候选也分到一点。

    09第五步：抽一个字，温度决定胆子大小

    有了概率表，最省事的做法是每次都挑第一名，但这样容易写出呆板、重复的话。所以模型通常按概率抽签：概率 60% 的候选，十次里大约被抽中六次。

    抽签前还可以调一个旋钮叫温度（temperature）：把所有分数先除以温度再做 softmax。

    • 温度低（比如 0.2）：高分被放大，第一名几乎包揽，回答稳定但死板；温度接近 0 时就等于每次都选第一名。
    • 温度高（比如 1.5）：分数差距被压平，冷门的词也有机会，回答更有创意，也更容易跑偏。

    抽中一个 token 后，把它接到句子末尾，整段文字再送回模型，再猜下一个。这样一圈一圈地转，直到写出「结束」符号。这就是为什么聊天机器人的回答是一个字一个字冒出来的。

    ⚠️ 这是一个玩具模型：它只在约 70 句我们手写的短句上「数次数」（三元语法 n-gram），最多只看前 2 个词（黄色高亮的部分），分数就是出现次数的对数。真实的大模型用的是前面讲的 Transformer，词表有几万个 token，能看前面成千上万个 token，但「出概率、按温度抽一个、接上再猜」这个流程是一样的。

    多玩几次，你大概会发现：

    • 开头是「床前明月」时，几乎只有一个答案，因为它「背」过这句诗；
    • 温度调到 0.1，每次都写出同一句；调到 2.0，会出现「今天天气很冷，记得带伞」之类拼接出来的新句子；
    • 输入它没见过的词，它只能退回去看更少的字，甚至瞎猜。真实的大模型看得远、见得多，所以猜得准得多，但它仍然是在猜，这也是它有时会一本正经地编造事实的根源。

    10背后要用到哪些技术和算力

    前面说的每一步，落到电脑上几乎都是同一种计算：一大堆数字的乘法和加法（矩阵乘法）。3Blue1Brown 统计过，GPT-3 的 1750 亿个参数被组织成近 28,000 个矩阵。这种计算可以拆成成千上万份同时做，最适合显卡（GPU），这也是显卡成了 AI 时代最紧俏硬件的原因。

    一个真实的例子：Llama 2 70B（Meta 2023 年发布的开放权重模型；数字来自 Karpathy 的公开讲座和 Meta 的模型卡）

    • 参数：700 亿个，每个用 2 个字节存，整个模型文件约 140 GB。
    • 训练数据：约 2 万亿个 token，Karpathy 估算相当于约 10 TB 文本。
    • 训练：Karpathy 估算约 6000 块 GPU 跑 12 天左右，GPU 费用约 200 万美元。
    • 使用：训练好以后，运行它只需要这个参数文件加几百行代码，在一台好一点的电脑上就能跑（只是慢）。

    可以看出：训练很贵，使用相对便宜。今天最强的模型规模和训练花费多半没有公开，但普遍比这个例子大得多。

    11记住这些就够了

    1. LLM 本质上是在猜下一个 token：算出所有候选的概率，抽一个，接上，再猜。长回答就是这样一个一个接出来的。
    2. 它猜之前要做三件事：把文字切成 token，把 token 变成向量，再用注意力让每个词结合上下文。Transformer 就是把这几步叠了几十上百层。
    3. 温度决定它保守还是大胆。它说得再流畅也只是「最可能的接法」，不保证是事实，重要的信息要自己核对。
